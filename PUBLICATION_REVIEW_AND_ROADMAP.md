# Publication Review & Roadmap (Bubble-Overlap Networks + FRM + TGNN)

This document is the single source of truth for: (1) what the paper is claiming, (2) what the code actually does, (3) what a harsh reviewer will challenge, and (4) the concrete milestones to reach a publishable, reproducible state.

## Current status (from code reality)

**What exists and runs today**
- End-to-end pipeline entrypoint: `scripts/run_pipeline.py`
- Core modules: `src/bubbles_networks/`
  - Bubble descriptive plots: `src/bubbles_networks/descriptive_bubbles.py`
  - Bubble overlap chart: `src/bubbles_networks/bubble_overlap_chart.py`
  - Aggregate overlap network: `src/bubbles_networks/network_aggregate.py`
  - Temporal bubble graphs (PyG snapshots): `src/bubbles_networks/temporal_network.py` → `results/temporal_graphs.pkl`
  - Centrality analytics + plots: `src/bubbles_networks/centrality_analysis.py`
  - FRM (rolling quantile regression) temporal graphs: `src/bubbles_networks/frm_network.py` → `results/frm_graphs.pkl`
  - TGNN forecasting: `src/bubbles_networks/tgnn_forecasting.py` + wrapper `scripts/run_tgnn.py`
- Paper source: `documents/main.tex` (build output: `documents/build/main.pdf`)

**What is explicitly *not* part of the active pipeline**
- Stochastic dominance (SD): isolated under `legacy_sd/` (see `legacy_sd/README.md`)

**Artifact policy (implemented)**
- `figures/` and `results/` are treated as generated artifacts (not tracked); kept via `.gitkeep`.
- `*.pkl` generated by runs is not tracked.

## Harsh reviewer lens (what will be challenged)

### 1) Identification and causality
- Why does “earlier bubble start → later bubble start” imply contagion rather than common shocks?
- Are edge directions robust to alternative bubble dating and overlapping definitions?
- How sensitive are results to the bubble detection model/sheet generation that produced the Excel inputs?

### 2) Network construction validity
- Are nodes consistently defined over time (firm universe changes, missing firms, delistings)?
- Are there artifacts from imputations / missing ΔCoVaR values?
- Does the network become too sparse/dense at certain times and bias centrality measures?

### 3) Centrality and systemic risk interpretation
- Why eigenvector/degree/betweenness (and not alternatives)? How is interpretation justified economically?
- Do centrality time series correlate with known crisis periods or market drawdowns (face validity)?

### 4) FRM module (optional) credibility
- Quantile regression choices (quantile level, regularization `alpha`, edge threshold) need justification.
- Runtime scaling: reviewer will ask if results are feasible/reproducible without bespoke hardware.

### 5) TGNN forecasting rigor
- Proper temporal splits (no leakage), strong baselines, and robust evaluation metrics are mandatory.
- Stability across random seeds and hyperparameters must be reported.
- Reproducibility requires logging configs, seeds, and environment.

### 6) Reproducibility and data provenance
- Where do the RO / STOXX600 Excel files come from, and are they shareable/licensed?
- Data dictionary (variables, units, missingness) must exist.
- One-command build should reconstruct all figures/tables referenced in the paper.

## Milestones

### M0 — Repo + reproducibility foundation
Deliverables:
- `src/` package + `scripts/` entrypoints stable and documented.
- Artifact policy implemented (`figures/`, `results/` untracked; `.gitkeep` present).
- Paper build command produces `documents/build/main.pdf`.
- Documented environment setup (`requirements.txt` and `requirements-lite.txt`).

### M1 — Data dictionary / provenance (RO + STOXX600)
Deliverables:
- `data/README.md` describing each dataset and sheet (RO + STOXX600).
- Variable definitions for:
  - Bubble episode tables (Firm/Start/Peak/End/Duration)
  - ΔCoVaR sheet (Date + firm columns; units, sign conventions)
  - Returns sheet (Date + firm columns; preprocessing assumptions)
- Clear provenance statement (source, access rights, and what can be shared).

### M2 — Baseline bubble-overlap network construction + validation checks
Deliverables:
- Sanity checks:
  - bubble episode count distribution
  - overlap edge density over time
  - invariants (no self-loops; edge direction rule adherence)
- Rebuildable temporal graphs with a configable output path.
- Minimal “network validation report” (markdown + plots) saved under `results/`.

### M3 — Temporal network + centrality analytics robustness
Deliverables:
- Sensitivity analysis:
  - alternative edge weighting (overlap days vs binary)
  - filtering rules for small networks
  - centrality measure stability (rank correlation across variants)
- Export centrality time series tables to `results/` (CSV/Parquet).

### M4 — FRM dynamic networks (optional) + runtime controls
Deliverables:
- Runtime controls documented (window, threshold, parallelization, start date).
- Diagnostics:
  - edge density and coefficient distributions
  - stability across thresholds
- Optional “FRM vs bubble network” comparison (overlap of central nodes over time).

### M5 — TGNN forecasting protocol
Deliverables:
- Fixed forecasting task definition (target variable and horizon).
- Train/val/test split protocol with no leakage.
- Baselines (e.g., persistence, rolling mean, simple regression).
- Metrics (MSE/MAE + rank metrics if relevant).
- Reproducible experiment runner that logs configs + seeds + outputs.

### M6 — Main paper results + robustness suite
Deliverables:
- All figures/tables referenced in the paper are reproducible from a documented command.
- Robustness: alternative bubble definitions, thresholds, time periods, and seeds.
- Clear mapping: each major claim → code path → artifact output.

### M7 — Final paper polish + release tag
Deliverables:
- Final LaTeX build reproducible (CI or documented local steps).
- Frozen environment spec for archival.
- Git tag for the release + archived artifacts (Zenodo/OSF if applicable).
